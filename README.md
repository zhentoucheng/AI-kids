# AI 带娃 · keke & kaoguan

**客厅里那台音箱，会自己开口。**

门锁一响，它知道是谁回来了，接上话放当天的英语；
孩子往沙发上一坐，坐够 40 秒，它出一道单词题。

不买硬件，不租算力。用的是你家里已经有的门锁、摄像头、音箱，和免费的大模型额度。

[主页](https://laocheng.dpdns.org/ai-kids.html) · [踩坑清单](#踩过的坑) · [快速开始](#快速开始)

</div>

## 为什么做这个

孩子这一代，一出生就被信息淹着。手机、平板、短视频，点开就有，永远刷不完。

不给看，不现实；随便看，他那点自控力又顶不住。

我琢磨了很久，想明白一个朴素的道理：**这个时代，家长最该干的活儿，是当那个筛子**——把跟年级对得上的东西挑出来，递到面前。

筛完还有第二件事：得有人陪着、盯着、提醒着。可大人要上班、加班、做家务，不可能每天雷打不动坐在旁边。

那就把这份「陪伴」交给 AI。它的好处很朴素：**准点、不偷懒、还认得出是谁**。

## 两个角色，共用一张嘴

```
            门锁指纹              客厅摄像头             定时
               │                     │                   │
               ▼                     ▼                   ▼
        ┌─────────────┐       ┌─────────────┐     ┌─────────────┐
        │  回家播英语  │       │  小考官      │     │   管家 keke  │
        │  (HA 自动化) │       │  kaoguan    │     │              │
        └─────────────┘       └─────────────┘     └─────────────┘
               │                     │                   │
               └─────────────────────┴───────────────────┘
                                     ▼
                              🔊 同一台音箱
```

| 链路 | 触发 | 干什么 |
|---|---|---|
| **A 回家播英语** | 门锁指纹 | 推开门约 25 秒后，音箱自动放当天的英语 |
| **B 客厅随机抽考** | 摄像头数到人，且坐够 40 秒 | 出题 → 念完 → 过一会儿自动报答案 |
| **C 管家主动开口** | 到点 / 有人进门 / 两个孩子打闹 | 问候、追问作业、劝一句、睡前收个尾 |

三个服务抢同一个喇叭，所以有一层互斥：谁在说话，别人闭嘴。

## 硬件

不用为这个项目买任何东西。我这边是三台 NAS 分工，这两个容器跑在**最旧的那台**上：

| 层 | 设备 | 跑什么 |
|---|---|---|
| 服务层 | 群晖 NAS（8G 内存） | Home Assistant、Frigate、**这两个容器** |
| 存储层 | 飞牛 NAS | 照片备份、远程打印 |
| 应用层 | 飞牛 NAS | 孩子英语打字、Zabbix 监控 |

**0 块独立显卡，0 元模型成本。** 视觉判断走免费的 flash 级模型（任何 OpenAI 兼容接口都行，换成你自己的）。

慢是真的慢：Frigate 用 CPU 检测器，单帧约 230ms。但判断「客厅有没有人、孩子在干嘛」，这个速度够用。

> 家里已经有 Home Assistant 和一台能念文本的音箱，这套东西才谈得上能跑。往下看「你需要先有的」。

## 快速开始

### 你需要先有的

这套东西是**拼装件，不是开箱即用的产品**。先确认这三样已经跑起来了：

- **Home Assistant** —— 提供播报出口（`text.*_play_text`）和门锁实体
- **MQTT broker** —— 两个容器靠它互斥，随便一个 mosquitto 都行
- **go2rtc / Frigate** —— 提供摄像头抓帧（`/api/frame.jpeg`）和人数统计

还有一台能说话的设备（小爱音箱之类，能被 HA 控制念文本）。

### 跑起来

```bash
git clone https://github.com/zhentoucheng/AI-kids.git
cd AI-kids

cp keke/config.example.yaml keke/config.yaml
cp kaoguan/config.example.yaml kaoguan/config.yaml
cp kaoguan/questions.example.yaml kaoguan/questions.yaml

# 改掉 config.yaml 里所有标 ★ 的项（地址、token、实体名）
vim keke/config.yaml kaoguan/config.yaml

docker compose up -d
docker compose logs -f keke
```

### 先别急着让它说话

两个容器都带了预演模式，**不联网、不出声**，先在本地把逻辑跑通：

```bash
# 管家：假装现在是 16:40，假装妹妹刚进门，看它会说什么
docker exec keke python keke.py --steward-dry --at 16:40 --fake-arrival --fake-who 妹妹 -v

# 管家：只测播报通道通不通
docker exec keke python keke.py --test-speak "播报测试"

# 小考官：只测看图判断，不出题
docker exec kaoguan python kaoguan.py --test-vision

# 小考官：看读到哪些词表、各多少个词
docker exec kaoguan python kaoguan.py --list-words
```

`--date` 参数别忘：不加的话当天已经触发过的事件会被跳过。

## 两个组件

### keke · 管家

三张嘴：

| 通道 | 谁主动 | 触发 |
|---|---|---|
| `wake` | 人 | 喊「小克」（带同音容错） |
| `fill` | 小爱 | 它答不上来，且话里带视觉意图 |
| `steward` | **它自己** | 到点 / 有人进门 / 孩子在打闹 |

五个主动事件：放学问候、假期问候、作业追问、打闹提醒、睡前收尾。
静默时段 `22:00–07:30`，这个区间内不主动开口。

**一个细节让它不像机器**：孩子答一句「还不会」，它记进 `memory/2026-11-05.jsonl`。第二天读到这条，作业追问自动改成——

> 「昨天那道题，今天搞会了吧？」

不是什么高级记忆架构。就是一个 jsonl 文件，加一句第二天的追问。但孩子以为它记得。

### kaoguan · 小考官

```
摄像头数到 ≥1 人
  → 坐够 40 秒（滑动窗口，掉线 20s 内不清零）
  → 过三道闸：时段 / 间隔 / 今日额度
  → 随机延迟 0–30 秒
  → 判「谁在家」：人脸 ∪ 门锁名单（取并集）
  → 加权随机点名（没点过的 ×3，刚连点 2 次的 ×0.01）
  → 出题 → 开口
  → 「念题估算时长 + 15 秒」后自动报答案
```

| 闸门 | 默认值 | 为什么 |
|---|---|---|
| 时段 | 09:00–20:30 | 放学后到睡前，太早太晚都不打扰 |
| 间隔 | ≥ 30 分钟 | 别连着问 |
| 额度 | ≤ 30 次 / 天 | 别烦到孩子被拔电源 |

出题来源：**看图 90% / 年级词表 10%**，题库只在两路都拿不到素材时兜底。视觉失败自动落回词表，保证出题不中断。

这两个比例在 `config.example.yaml` 的 `vision_ratio` / `words_ratio` 里，改完重启就生效，没有别的硬编码。**以配置文件为准**——你按自己的模型能力和网速调，不一定要跟着默认值。

画面 0 人绝不出题。这条是硬约束。

## 踩过的坑

这部分比代码值钱。每一条都是实测出来的，不是想出来的。

### 1. 单帧看图判定 = 掷骰子

同一张静止画面，同一个模型，同一个提示词，连问 15 次：

```
打闹 ×8    安静 ×2    空 ×4
```

**改法**：一次抓 3 帧一起丢给模型，再加 `min_people=2` 硬防线。连续 2 次都判「打闹」才开口。

### 2. 门锁绝不能读「当前状态」

真实序列是 `outside_unlock` → 几秒后自动 `lock_inside`。轮询到时早就变了，读当前值**必然漏掉每一次进门**。

**改法**：`/api/history/period` 在时间窗内找事件点。任何「当前状态」都可能是过期的，只有事件流是真实的。

### 3. 定时事件必须排在「要不要看一眼」型检查之前

打闹检查的时段盖住了睡前问候，结果睡前那条永远不触发。分支顺序是有代价的。

### 4. 唤醒词同音容错

喊「小**克**」被云转写成「小**客**」「小**柯**」「小**哥**」。精确匹配必然漏。

**改法**：`小X` 前缀 + 同音字表，再叠一层**假阳性词表**——必须含「小」+同音字的整词才算否决，比如「小哥哥」「小可爱」「小柯基」。

### 5. 门锁信号是概率性丢包

米家消息实体是**单值实体**，「门外开锁」会被紧随的「门已上锁」顶掉。`lock_action` 卡在云轮询，实测能停在几小时前的值不动。

**改法**：两路并行 + `lock_key_id` 时间戳跳变兜底，三源探测。

### 6. 群晖的 `db` 日志驱动会假死

容器显示 `Up`，其实已经死了。曾经假死 5 天没人发现，SQLite 管道灌满。

**改法**：全部改成 `json-file` + 轮转。这条和本项目无关，但在群晖上跑任何常驻容器都要注意。

### 7. 小米云对话记录的 device_id 不是 token 里那个

对话记录接口按 deviceId 过滤，而这个 deviceId 必须是**音箱**的 UUID，不是 token 里「登录设备」的 ID。传错 → 接口返回 `code=0` 但 `records` 恒为空，看着像「这孩子今天没说过话」。

更细的记录在 [docs/pitfalls.md](docs/pitfalls.md)。

## 它做不到什么

**它替代不了家长。**

它不会判断孩子今天情绪好不好，不会发现她哪门课开始跟不上，也不会替你说那句「你今天很努力」。

它只是把「每天都得有人提醒」这件事，变成不需要人盯着。

如果你指望装完孩子成绩就上去，那这套东西会让你失望。它解决的是「没人有空天天陪」这个具体问题，不是「教育」这个大问题。

## 隐私

这个项目里所有配置都是模板，**不含任何真实凭据**。你填的 `config.yaml` 被 `.gitignore` 挡住，不会被误提交。

但你要清楚：这套系统的输入是**家里的摄像头画面**和**孩子的语音**，输出要经过**第三方大模型接口**。

- 介意的话，把视觉模型换成本地跑的（Qwen-VL / MiniCPM-V 之类），NAS 也能跑得动小模型
- 只做人数统计不出题，`quiz.vision_ratio: 0`
- 孩子房间别装摄像头，客厅就够
